## 1. 성숙도 정의

| 수준 | 의미 | 산출물 | 개발 착수 |
|:---:|---|---|:---:|
| **L1** | 영역/기능이 식별됨 | 기능 영역 정의서 | ✗ |
| **현행** | 운영 중이나 요건 문서(L2·L3) 없음 — 인수 시스템 | 현행분석서 + 코드 | 변경 시 L2 역산 후 |
| **L2** | 기능 목록 + 데이터 개요 확정 | 영역별 요건서 | ✗ |
| **L3** | 처리 규칙 + 인수 조건 확정 | 개발 요건 정의서 | ✓ |
| **DONE** | 개발 완료 및 검증 통과 | 코드 + 테스트 | - |

> ※ **L3가 아닌 기능은 개발에 착수하지 않습니다.** 현행 기능을 변경할 때는 해당 영역 L2 를 그때 역산한 뒤 L3 로 올립니다.

## 부록 — 운영 규칙

### 주간 점검 항목

- [ ] 다음 주 개발 대상 기능이 L3로 올라와 있는가
- [ ] 미결정 사항 중 결정 시점이 임박한 것이 있는가
- [ ] 블로커가 3일 이상 해소되지 않은 것이 있는가
- [ ] P0 기능 중 L2에 머물러 있는 것이 있는가
- [ ] 변경 요청이 들어온 현행 기능의 영역 L2 가 역산돼 있는가

### 성숙도 상승 조건

**L1 / 현행 → L2** — 해당 영역의 L2 완료 판정 항목 전부 충족

**L2 → L3** — 개발 요건 정의서 작성 완료, Blocker 질문 100% 응답, 인수 조건(Given/When/Then) 작성

**L3 → DONE** — 구현 완료, 인수 조건 기준 검증 통과, 코드 리뷰 완료
