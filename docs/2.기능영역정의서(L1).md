## 1. 플랫폼 정의

### 1.1 해결하려는 문제

운영시스템(현재 2개, 추가 예정)의 변경·배포 요청, 팀 보고, 손익, 과제 관리가 흩어져 있어 한곳에서 추적·공유할 수 없다. `[근거: CLAUDE.md 업무 요건]`

### 1.2 목표

팀 내부 업무(요청 → 승인 → 배포 → 보고)가 포탈 안에서 끝나고, Redmine·Webex 같은 기존 도구와는 연동으로 이어진다. `[현행 기준 — 서비스정의서가 없어 CLAUDE.md 와 코드에서 역산. 확인 필요]`

### 1.3 하지 않을 것 (Out of Scope)

- Redmine 대체 — 일감 원장은 Redmine, 포탈은 연결만 `[현행: ChangeRequestIssue·DeployRequestIssue 가 redmineIssueId 만 보관]`
- AI 서버 자체(모델·RAG·지식베이스) — 별도 시스템, 포탈은 화면과 프록시만 `[현행분석서 2.2절]`
- 외부(현업) 직접 접속 — EXTERNAL 역할은 협력사 계정 수준 `[현행: EXTERNAL 메뉴 1개(변경 관리)만 허용]`
- `[확인 필요]` 그 외 명시된 제외 범위 없음

## 4. 영역 간 관계

### 4.1 의존 관계

```
A-01 인증·사용자 ─┬→ A-02 운영시스템 마스터 ─┬→ A-03 변경 요청 ─┐
                  │                          ├→ A-04 배포 요청 ─┼→ A-08 To-Do (sourceId)
                  │                          └→ A-06 일일점검   │
                  ├→ A-09 메뉴 권한                             └→ A-12 대시보드
                  ├→ A-06 주간보고·회의록 (username)
                  └→ A-11 AI (username 만 전달, 인증 없음)
A-10 알림·연동 ←── A-03, A-04 (Redmine 동기화), A-04·스케줄러 (Webex), A-01 (메일)
A-05 인벤토리, A-07 손익 — 독립
```

### 4.2 개발 순서

> 신규 구축이 아니므로 "착수 순서"가 아니라 **변경 작업 순서**. 현행분석서 12절 결함 8건과 10절 미결정이 기준.

| 차수 | 영역 | 비고 |
|---|---|---|
| 1차 | A-01 권한·식별 모델 결정 (10절 ①~④) | 다른 영역의 결함 수정이 이 결정에 종속 (#9, #10, #15, #19) |
| 2차 | A-03, A-04 결함 수정 (#4 채번, #10 단계 완료 권한) + 현행 동작 고정 테스트 | P0 영역 |

## 10. 미결정 사항

> 현행분석서 5절 경계 불분명 4건 + 12절 "미고려" 4건. **①~④는 하나의 결정(권한·식별 모델)** 로 묶어서 정하는 것이 효율적.

| 항목 | 미결정 사유 | 영향 영역 | 결정 필요 시점 |
|---|---|---|---|
| ① 소유자 검사 (12절 #9) | 보고류·To-Do·업무단위를 남이 수정·삭제 가능. 팀 내부 상호 수정 허용인지 | A-06, A-08 | 1차 — 변경 작업 전 |
| ② 사용자 참조 방식 (12절 #2) | FK vs username 문자열 통일 여부. 통일하면 보고 화면에 이름 표시 가능 | A-06, A-08, A-04(DeployStep.completedBy) | 1차 |
| ③ AI 연동 인증 (12절 #6) | AI 서버 호출에 JWT 전달·검증 체계. 운영 노출 전제 | A-11 | A-11 운영 노출 전 |
| ④ EXTERNAL 권한 범위 (12절 #15) | 변경요청 승인 불가 vs 배포 비RELEASE 승인 가능. 협력사 계정의 역할 정의 | A-01, A-03, A-04 | 1차 |
| ⑤ 보고 영역 분할 (5절 C-06) | 메뉴 3개 / 패키지 1개. L2 를 셋으로 쓸지 하나로 쓸지 | A-06 | A-06 L2 착수 전 |
| ⑥ 과제·업무단위·To-Do 경계 (C-08) | 패키지 3개가 한 업무 흐름인지. `sourceId` 다형 참조 유지 여부 | A-08 | A-08 L2 착수 전 |
| ⑦ 연동 로직 위치 (C-10) | Redmine 동기화가 요청·배포 서비스 안에 섞임. 영역으로 분리할지 | A-03, A-04, A-10 | A-10 L2 착수 전 |
| ⑧ AI 영역 소속 (C-11) | 이 저장소에선 프록시+화면뿐. 포탈 L1 에 둘지 AI 서버 L1 로 넘길지 | A-11 | ③ 과 함께 |
| ⑨ 스키마 관리 | 마이그레이션 도구 도입 여부·시점 | 전체 | 다음 스키마 변경 전 |
| ⑩ `nginx.conf` 용도 (12절 #21) | 프론트 컨테이너 배포 계획이 있는지, 없으면 삭제 | 배포 | 설계 단계 |

> ※ ①~④, ⑨는 L2 범위를 바꾸므로 **L2 착수 전 해결**. ⑤~⑧은 해당 영역 L2 착수 전. ⑩은 rsp-design-arch 로 인계.

## 11. L1 완료 판정

| 판정 항목 | 기준 | 충족 |
|---|---|:---:|

| 우선순위 | P0/P1/P2 구분 완료 | ☐ (제안 상태) |

| Out of Scope | 명시 완료 | ☐ (확인 필요 1건) |
| 미결정 사항 | 목록화 + 결정 시점 명시 | ☑ |
