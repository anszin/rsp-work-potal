## 1. 영역 개요

### 1.1 이 영역의 목적

승인된 변경을 운영시스템에 올리는 과정을 **요청 → 승인 → 서버별 단계 완료 → 완료** 로 기록하고, Redmine 버전과 Webex 알림으로 바깥에 알린다. (L1 3절 A-04, 서비스정의서 시나리오 2)

### 1.2 범위

| 구분 | 내용 |
|---|---|
| 포함 | 배포 요청 등록·수정·삭제, 상태 전환(제출·승인·반려·완료), 서브시스템 서버별 배포 단계 완료, Redmine 버전 생성·일감 fixed_version 반영, Webex 알림, 부분 배포 뒤 후속 전체 배포, 목록 조회·필터, 배포 현황 집계 |
| **제외** | 운영시스템·서브시스템·서버 기준 정보(A-02), Redmine·Webex 클라이언트 자체(A-10, 이 영역은 "언제 무엇을 보내나"만), 변경 요청(A-03) — 배포 요청은 변경 요청과 데이터로 연결되지 않음(`확인 필요`: 연결 의도가 있었는지), 대시보드 카드(A-12) |

### 1.3 주요 사용자

| 사용자 | 이 영역에서 하는 일 |
|---|---|
| 시스템 담당자 (MEMBER, `system_managers` 등록) | 요청 등록·제출, 비릴리즈 승인·반려, 단계 완료, 완료 처리 |
| MANAGER / ADMIN | 모든 시스템의 승인·반려(릴리즈는 이들만), 완료, 완료 건 사후 수정 |
| MEMBER (담당자 아님) | 요청 등록·초안 수정·조회만. 제출·승인·단계 완료 불가 |
| EXTERNAL | 메뉴·API 모두 불가 (L1 ④, F-AUTH-001 R-006) |

## 3. 업무 흐름

### 3.1 주요 시나리오

**시나리오 1 : 전체 배포 (서비스정의서 시나리오 2)**
```
1. 담당자가 배포 요청 등록 (유형·범위·버전·Redmine 일감) → 초안
2. 담당자가 제출 → REQUESTED, Webex 알림
3. MANAGER 승인 → APPROVED. Redmine 버전 생성·일감 fixed_version, 서브시스템 서버 수만큼 단계 생성, Webex 알림
4. 담당자가 단계를 순서대로 완료 → 단계마다 "배포 진행 n/n" 알림
5. 마지막 단계 완료 → 자동 COMPLETED, deployedAt, "전체 배포 완료" 알림
```

**시나리오 2 : 부분 배포 뒤 후속 전체 배포 (F-DR-008)**
```
1. 범위 PARTIAL(대상 명시)로 시나리오 1 진행 → COMPLETED
2. 목록에서 "후속 전체 배포" → 같은 시스템·제목·버전·일감으로 범위 FULL 자식 요청 초안 생성
3. 자식 요청이 시나리오 1 을 다시 밟음. 목록에서 부모 아래 펼쳐 보임
```

**시나리오 3 : 담당 시스템만 보기 (F-DR-006, 이번 요청)**
```
1. 배포 관리 진입 → 시스템 Select 기본 "전체"
2. 자기 시스템 선택 → 목록·페이지 1·현황 탭 집계가 그 시스템 기준
3. 상태 버튼과 조합 ("A 시스템 승인 대기")
```

### 3.2 상태 전이

(`DeployRequestService.ALLOWED_TRANSITIONS`, `DeployStepService.complete`)

| 상태 | 설명 | 다음 가능 상태 | 전이 조건 |
|---|---|---|---|
| DRAFT | 초안. 누구나(등록자 포함) 수정, 삭제 가능 | REQUESTED | 담당자∥관리자 |
| REQUESTED | 제출됨, 승인 대기 | APPROVED, REJECTED | 릴리즈: 관리자만. 그 외: 담당자∥관리자 |
| APPROVED | 승인. Redmine 버전·단계 생성됨 | COMPLETED | 담당자∥관리자, 전 단계 완료 뒤. 또는 마지막 단계 완료로 자동 전이 |
| REJECTED | 반려(사유 기록) | — | 종료 |
| COMPLETED | 배포 완료(deployedAt). 관리자만 메모 수정 | — | 종료 |

단계(DeployStep): PENDING → DONE (완료자·시각 기록). 되돌리기 없음.
