# 7. 현행 분석서 — 플랫폼팀 업무 포탈 (rsp-work-potal)

> **이 문서는** 이미 개발·운영 중인 시스템을 인수할 때, **코드에서 역산해** 현재 구조와 동작을 기록하는 문서입니다.
> 신규 구축의 1→4 흐름과 달리, 이 문서가 L1 기능영역정의서와 설계 패키지의 **초안 입력**이 됩니다.
>
> | | |
> |---|---|
> | **몇 개 쓰나** | 시스템당 **1개** |
> | **앞 문서** | 없음 (소스코드, 운영 자료가 입력) |
> | **다음 산출물** | 2.기능영역정의서(L1) 초안, 설계 패키지(`design/`) 초안, 참조 자산(코딩컨벤션·아키텍처 표준) 초안 |
> | **작성 시점** | 시스템 인수 직후 1회. 이후 큰 구조 변경 시 갱신 |
> | **작성 주체** | AI 주도, 인수 개발 리드 검증 |
>
> **목적** : 지금 시스템이 **어떻게 되어 있는지**를 근거와 함께 기록한다. 왜 그렇게 만들었는지는 기록하지 않는다.
> **작성 원칙** : 모든 항목에 **근거(파일 경로)** 를 적는다. 코드에서 읽어낸 것과 추측한 것을 섞지 않는다.

## 4. 구조

### 4.1 계층·모듈 구성

```
[FE] pages/ ─→ api/ (axios client, Bearer) ─→ /api/** ─→ [BE] api/ (Controller 16)
                                                              └→ domain/{기능}/service ─→ repository ─→ PostgreSQL
                                                              └→ service/ (Redmine · Webex · Mail · FileStorage · Scheduler)
     pages/Ai* ─→ api/aiApi.ts (fetch/XHR, 인증 헤더 없음) ─→ /api/{chat,agent,documents,prompts,knowledge,conversations} ─→ [AI 서버] (미조사)

  (예외) BE api/AuthController, api/RedmineController 가 Repository 직접 호출  [11절 레이어 예외]
```

- C-08: `todos.source_id` 가 `source_type`(SELF/CHANGE_REQUEST/DEPLOY/EXTERNAL) 에 따라 C-03·C-04 를 다형 참조. `work_units.key_task_id` 는 FK 없는 Long. 세 패키지가 한 업무(과제 → 업무단위 → 할 일)인지 별개인지 불명. → **L1 ⑥ 결정 (2026-10-21)**: 한 영역(A-08). 추가 관찰: `source_id` 는 BE 가 채운 적 없고 FE 폼도 입력받지 않음(2026-08-13 도입 후 미연결) → 폐기, 컬럼 삭제는 ⑨ 이후
- C-10: Redmine 동기화 로직이 `ChangeRequestService`·`DeployRequestService` 안에 들어 있어 C-03·C-04 와 섞임. Webex 알림은 C-04 와 스케줄러에서만 발생. → **L1 ⑦ 결정 (2026-10-21)**: A-10 = 어댑터 + 공지 화면, 호출 정책은 각 영역(현행 유지). 이벤트 분리는 레드마인 대체 결정 후 재검토
- C-11: 이 저장소 기준으로는 "프록시 + 화면" 뿐. 영역으로 둘지, AI 서버 쪽 L1 에서 다룰지 결정 필요. → **L1 ⑧ 결정 (2026-10-20)**: 포탈 A-11 은 화면 + 프록시까지, 나머지는 AI 서버 L1
